# Roadmap decision — 2026-09-07

Decided after a full read of the branch state and every September handoff. Companion to
`docs/STATE_OF_EVIDENCE_2026-09-07.md`, which holds the numbers; this document holds the
choice and the reasoning. Goals weighted by the user: research findings + portfolio, and a
usable Ledger component.

## Where the project stands

- One live line (Euglena Ledger). DAG v2's "next step" (barrage relaunch) had not been touched
  since 2026-08-19 and no September document mentions it.
- `master` was frozen at 2026-08-19 while the branch ran 325 commits ahead; the entire pivot
  and ~1,300 tests existed only on the branch. README described a 1,951-test suite and
  "nothing adaptive is proven yet". Merged fast-forward today.
- The Ledger's defensible claim is auditability at no accuracy cost, not mean score.
- The structural bottleneck is upstream of everything the verifier checks: 120/144 cells mint
  zero derivations; `derive` adoption is a cliff at 7b; finish-time coercion failed.
- Built-but-inert code is accumulating (`unified_verdict`, `Interval`, `recheck_*`,
  `FinishGate`, the evidence-queue stub). "Green tests, never executed" has recurred five times.
- The largest measured effect in the repo (graph −0.461 on aggregation shape, n=23) has a
  named cause and an unrun, cheap, deterministic intervention.

## The paths considered

| # | Path | Cost | What it buys |
|---|---|---|---|
| 1 | Consolidate and tell the true story: merge, README, superseded markers, state-of-evidence doc | Small, $0 | Coherent front door; every later result inherits it |
| 2 | Break the zero-derive wall: mechanical row minting from the quantity index + operand-provenance filter + require a computed result for clause 5 | Medium, $0 | The only lever that moves coverage from ~10%; decouples auditability from model compliance; kills the 4 wrong-entity vindications |
| 3 | Make the component real: fix `ledger_api.py` defects, freeze `LedgerResult` contract, package, one external consumer | Medium, $0 | "Component, not agent" becomes demonstrable |
| 4 | Close measurement debts: seeded gpu0831 rerun, L5 replay fidelity, doc downgrades | Small, GPU hours | The pivot rationale stops resting on an unseeded null |
| 5 | Aggregation-shape 2×2: {linear, deterministic worklist} × {prose, typed records} on 23 tasks | Large | The one candidate for a large, defensible finding; reframes the DAG as a dependency analyzer feeding a deterministic executor |

## Decision

Sequence **1 → 2 → 3**, with 4's doc corrections folded into 1 and its reruns scheduled
opportunistically. Then decide on 5:

- If step 2 lifts certify coverage materially (≥25% at ≤5% risk on a prereg'd corpus), invest
  in step 3's second host and hold there.
- If it does not, that is itself the finding, and step 5 becomes the next Large cycle.

## Retired explicitly

Written down so nobody re-attempts them:

- DAG v2 barrage relaunch and the `baseline → good_adaptive → max_burn` ladder.
- Phase B typed action queue ("nothing in the data says scheduling is the bottleneck").
- Finish-time coercion for sub-3B models (0 new derives, +543–820% tokens).
- Contradiction relaxation via `_is_wildcard` (~93% false positive).
- Unit or currency conversion in the derivation layer, ever.
- `Interval` wiring (1 real containment case in 11,786 stored values).
- v3 continuable chat and codebench: parked under "future", not on any live line.
- Powered n≈60 mechanism campaigns: the throttle is authored tasks (22 numeric; the 40
  generated ones are unvalidated and likely easier). Do not spend GPU-days on reruns that
  cannot resolve.

## Verification for each step

- Step 1: `git log master..dagv2-evidence-ledger` empty; README test count matches
  `pytest -q agent/tests`; a fresh reader reaches the current queue in one hop from README.
- Step 2: prereg committed before the campaign; the report shows coverage/risk against the
  frozen rule; the 4 mint02 vindication cells flip to rejected.
- Step 3: fresh clone, install, one script calls `ledger_api.run` on a 20,000-char supplied
  source and every claim offset re-verifies via `recheck_result`.
- Step 5: prereg'd 2×2, seeded corpus replay, effect reported with a confidence interval.
