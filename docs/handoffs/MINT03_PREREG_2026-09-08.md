## 1. Why there is no `host_derive` on/off LLM arm

`host_derive` is a **finish-time host hook**: no model call, no prompt change, no tool-list change.
It is called before `artifact()` and writes `execution.output.host_derive`. 2e confirmed this
empirically rather than only by construction — availability was 41.7% on derive-on cells and 35.9%
on derive-off cells, i.e. arm-independent to within a few points (`HOST_DERIVE_REPLAY_2026-09-08.md` §11).

Consequence: **every mint03 cell runs the hook on**, with
`LEDGER_HOST_MODULES=derive,answer_audit,shape_derive,host_derive`, and the host-on/host-off
contrast is taken **post-hoc from the same cells** — `host_certified` against the frozen 5-clause
chain `certified`, plus the two negative controls. Running a "host off" arm would be seed-identical
on the model side and would only burn GPU. This follows mint02's own precedent, which declined a
module-off arm for `shape_derive`/`answer_audit` for the same reason.

The **arms are therefore the two hosts**: `sequential_react` and `langgraph_react`.

### Why one manifest per (model × host) rather than mint02's one-per-model

mint02 wrote four manifests, one per model, each listing both hosts as `arms`. `scripts/prereg.py
audit` reports completion **run-wide**, so a host that died entirely inside one of those manifests
could be averaged away by its partner. Splitting to eight pins completion, infra-failure and
`min_usable_paired_n` to a single host each. This is a deliberate departure from the mint02
precedent; nothing else about the corpus design departs from it.

Run-ids are **distinct and non-prefixal** (all 11 characters, none a prefix of another). This
matters twice: `prereg.py:_cell_path` anchors on `^{run_id}.*_{task}_.*_{arm}` and would otherwise
let one run's cells satisfy another's denominator, and `ledger_risk_coverage.py --prefix` /
`host_derive_replay.py --prefixes` are plain filename-prefix matches. `--prefix mint03` picks up all
eight; each `--prefix mint03_sq7b` picks up exactly one. Arm-profile names never appear in result
filenames (`idea_test_runner.py:1740` writes `{run_id}_{test_id}_{model}_{execution_variant}{cfg}_r{rep}`,
where `execution_variant` is the host, not a profile), which is the other reason a per-arm manifest
is the only reliable per-arm denominator.

## 3. Page-storage knob — what was found, and why nothing changes

2e's closing paragraph named the Phase-1 truncation fix (pages stored as a 6000-char prefix) as the
next availability lever. Searched `agent/app/ledger_tools.py`, `agent/app/testing/execution_sequential.py`,
`agent/app/langgraph_solver.py`, `agent/app/idea_test_runner.py`, `agent/app/ledger_api.py`, plus a
repo-wide enumeration of every `LEDGER_*` environment variable. Findings:

- `LedgerToolkit.__init__(max_page_chars=6000)` (`ledger_tools.py:348`) caps the **stored** window,
  and `register_page` clips to it (`:377`). It reads **no environment variable**.
- `sequential_react` constructs `LedgerToolkit()` with **no argument**
  (`execution_sequential.py:762`), so its store cap is the hardcoded 6000.
- `langgraph_react` constructs `LedgerToolkit(max_page_chars=page_chars)`
  (`langgraph_solver.py:1744`) — the store cap is *bound to the model-visible* `page_chars`
  (default 6000, further reduced by `_context_fit_budget` when `LEDGER_CONTEXT_FIT=1`).
- **Both hosts truncate before registering.** `execution_sequential.py:644` does
  `content = (content or "")[:page_chars]` and then `register_page(url, content)`;
  `langgraph_solver.py:538` does `register_page(url, (content or "")[:page_chars])`. The stored
  text is a subset of the text the model saw, in both hosts.
- The only env knob anywhere on this path is **`IDEA_TEST_SEQ_PAGE_CHARS`** (`execution_sequential.py:509`,
  default `6000`), and it is **model-visible**: the same clipped `content` goes into the ReAct
  observation (`obs = f"PAGE {url}:\n{content}"`) and into the `evidence` buffer. `langgraph_react`
  has no env knob at all. `ledger_api.py:475` exposes a caller-controlled `page_chars`, but that is
  the library entry point, not the benchmark host path.

**Decision: no page-storage knob is set for mint03.** There is no store-only knob to raise. Raising
`IDEA_TEST_SEQ_PAGE_CHARS` would enlarge the model's context window on one host and not the other,
changing the very surface the seed-identity argument in §2 depends on and breaking host-vs-host
comparability. mint02's effective value (6000, unset) is kept on both hosts and stated here so the
availability ceiling attributable to truncation is a **known, unchanged** constant across mint02,
the 2e replay and mint03. Decoupling storage from the model-visible window is a host change and
belongs to the replan's Phase 1, not to this campaign.

## 4. Endpoints

Written so both outcomes are reachable. All figures come from
`scripts/ledger_risk_coverage.py --prefix mint03`, whose `dev_derive_on` population is every dev
cell here (all mint03 cells carry the `derive` token).

### PRIMARY — `host_certified` coverage ≥ 2 × chain `certified` coverage

- Denominator: **ALL dev cells** (72). Availability is reported beside it and is **never** the
  denominator.
- Sections: `host_vs_chain` (`chain_certified`, `host_certified`, `union`, `intersection`),
  `host_derive_dev_derive_on` (+ its `by_model`), `strata_by_model_dev_derive_on` (chain coverage
  per model).
- Success requires **both**: the pooled bar (host coverage ≥ 2× chain coverage over all 72 dev
  cells), **and** ≥3 of 4 models with host coverage non-decreasing against that model's own chain
  coverage. Either prong failing is a campaign failure, reported as such.
- 2e's dev read for calibration, not as a result: host 5.1% vs chain 7.1%, union 12.2% — the pooled
  bar was **not** met on stored cells. This endpoint can fail, and on the most recent evidence it is
  more likely to fail than to pass.

### CO-PRIMARY — `host_value_correct` ≥ 0.9 among computed cells

`host_value_correct_rate.dev_derive_on.rate` — the host's own value/winner against the task module's
ground-truth constants, independent of what the model answered. 2e measured **1.000 (113/113)** on
stored pages. A live drop below 0.9 means the mechanism is failing on fresh pages, and fails the
campaign **on its own**, whatever the coverage endpoint does.

### Risk — reported, not decision-bearing this phase

Wrong acceptances among `host_certified` cells, as an exact-binomial (Clopper–Pearson) 95% upper
bound. Per the replan it is decision-bearing only at **≥59 accepted cells**
(`ledger_risk_coverage.py:513`, `HOST_RISK_DECISION_MIN_ACCEPTED`). With 72 dev cells that needs 82%
coverage; 2e measured 5.1%. **State plainly: risk is a readout in mint03, not a gate.** It is
recorded so a later campaign with more cells can pool it.

### Controls — same table, both required to hold

1. **Availability-only baseline** (`host_availability_only_baseline`): accept every cell where the
   host computed anything. If its coverage/risk numbers equal `host_certified`'s, the agreement test
   is inert and the primary endpoint means nothing regardless of sign. 2e: 44.2% coverage at 43.5%
   risk — decisively not a certifier.
2. **`document_order` ranker ablation** (`scripts/host_derive_replay.py --prefixes mint03
   --rankers document_order,hand_rule`, post-hoc over the same cells, no re-run): the hand rule must
   stay above document order. 2e: 1.000 vs 0.306.
3. Also printed: chain-only, union, intersection (`host_vs_chain`).

### Escape hatches, closed

- **No single-model pass promotes.** Four models are run so the pooled bar has a per-model
  consistency check attached; a mechanism that only works on qwen2.5:7b is a negative result.
- **Conditional-on-available coverage is never the endpoint.** "X% of the cells where the host
  computed something" is a description of the mechanism's reach, not of its value; the denominator
  is all dev cells, full stop.
- **Secondaries are not outcomes.** `host_agrees` (final/any/entity), the availability reason table,
  the refusal mix, per-task availability, `union` coverage and every `answer_audit`/`shape_derive`
  section are descriptive. None of them may be reported as the campaign's result, and none of them
  may be substituted for a failed primary.
- **No threshold re-sweeping after unblinding**, for any endpoint, on any split.

### Holdout — sealed, reported separately, decides nothing

Tasks 213/217/221 run in the same campaigns (they are part of the 12) and land in
`host_derive`'s `holdout` split. Their numbers go in a **separate block** of the results document
and carry **no decision**. 2e already noted 217 and 221 are 0% available after the unit-mismatch and
slug-priority fixes, so the holdout has very little left to say; that is a fact about the corpus,
recorded in advance so a thin holdout cannot be read as a signal in either direction.

## 7. Launch recipe

**Do not launch anything until 2e's artifact is attached and the eight manifests are written.**
Both are done as of this file. Everything below is the recipe; this lane did not run it.

Rules, in force for the whole run:

- **One campaign at a time.** `scripts/run_campaign.sh` holds
  `agent/idea_test_results/_campaigns/campaign.lock` and refuses to start a second run against a
  live pid. That lock *is* the gpu-lock for ollama-contending work (DEV_CYCLE gate 3 and the
  "Parallelism" section): one single-threaded backend at `127.0.0.1:11435`, `IDEA_TEST_CONCURRENCY=1`,
  `OLLAMA_NUM_PARALLEL=1`. Two concurrent campaigns do not merely run slowly, they contend for VRAM
  and produce cells whose timings mean nothing.
- **Never `pkill -f`.** Stop a run with `scripts/run_campaign.sh --stop <run_id>`, which signals the
  process group by id. `pkill -f` has previously killed an unrelated session's job, and the shell
  running it.
- **Durability** is gate 5 and is already inside the script (`setsid nohup … < /dev/null & disown`).
  Do not background a run from an agent harness; harness-backgrounded campaigns die.
- **Do not edit `agent/app/**` while any mint03 campaign is running.** Host code must be one version
  across all 96 cells or the corpus is not one corpus. Record the launch commit; `run_campaign.sh`
  stamps it into each `.env`.
