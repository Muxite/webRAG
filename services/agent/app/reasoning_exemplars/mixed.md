# Reasoning exemplar — eliminate-to-one-survivor, then chain forward

Two phases. Phase 1 gives several genuine candidates and one criterion that only
ONE satisfies; find the survivor. Phase 2 uses the survivor's own page to reveal
a NEXT target unknowable until the survivor was picked — and that target may
itself be ambiguous.

STOP CONDITION — read this first: do not report any answer, even a partial one,
until BOTH phases are fully done — every candidate checked in Phase 1 AND the
terminal field read in Phase 2. Resolving only the survivor (or only some
candidates) is not a stopping point; it is the middle of the task, not the end.

## Phase 1 — parallel elimination (check all, guess none)

Situation: The prompt lists candidate 1, 2, 3, 4 and a distinguishing criterion.
One candidate is clearly the most well-known.
Thought: The famous candidate is a trap. The criterion, not fame, decides. I must
open the source page for EVERY candidate and read the one field the criterion
tests — I cannot skip a candidate because it "seems" right or wrong.
Action: Open each candidate's page; read the deciding field verbatim from each.

Situation: I now hold the deciding field for all candidates.
Thought: Exactly one matches; the rest fail for a stated reason. I record why each
is eliminated, so the survivor is proven by comparison, not assumed. The survivor
was NOT identifiable before this step finished.
Action: Name the single surviving candidate and its supporting field value.

## Phase 2 — forward chain from the survivor

Situation: I open the surviving candidate's own page.
Thought: This page — and only now that elimination is done — names the next
target. I could not have planned this hop in advance; it was contingent on which
candidate survived.
Action: Read the survivor's page to extract the next target it points to.

Situation: The next target is itself one of several like-named things.
Thought: A second mini-disambiguation. Same discipline: do not guess by
prominence; use the survivor's page to identify the SPECIFIC one it references
(e.g. by where they connect), then follow that exact one.
Action: Resolve the specific next entity, then open its page.

Situation: I am on the final resolved page.
Thought: The task wants one terminal fact — a specific infobox field. Reaching it
means: right survivor, right forward target, and this field read verbatim. Once
read, the chain is complete; stop.
Action: Read the requested field and report it, citing every page opened.

Key habits: (1) check every candidate; the obvious one is bait. (2) The
survivor's page, not prior planning, sets the next target. (3) A follow-on target
can be ambiguous too — re-apply check-don't-guess. (4) Do NOT stop after Phase 1,
even once a survivor is clear — Phase 2 is mandatory, not optional follow-up. (5)
Stop only once the named terminal field on the final resolved page has been read.
